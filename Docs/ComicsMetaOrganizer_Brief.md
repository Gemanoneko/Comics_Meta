# Comics Meta Organizer — Brief

**What it does.** A local background service for Sergei's YACReader comic library. It scans the library folder by folder, identifies each comic from what the comic itself says (a saved cover reading that agrees with the filename) or from external sources (ComicVine, Metron, GCD, Google Books, publisher/web research, an optional Open Library dump, Google Lens cover search), and writes verified `ComicInfo.xml` into CBZ archives. A backup is removed only after the written file reads back correctly and passes a SHA-256 check. **What Sergei does with it:** keeps it running, watches the dashboard, presses **Pause & release GPU** when he needs the computer, completes Google Lens human verification when the dashboard asks (Yandex is no longer searched since 2026-10-12), then runs YACReader's **Rescan library for XML info**. **What it does not do:** edit YACReader's database; solve CAPTCHAs or spoof browser fingerprints; write metadata from a search match alone, or from a cover reading that disagrees with the filename; take creators from a cover or a year from a copyright line; overwrite a value Sergei or another program wrote; overwrite a conflicting CBZ; start itself after a reboot; correct every existing populated field (unfinished).

## How to start and stop

1. Start **Comic Metadata** from the Start menu. There is no sign-in or startup trigger.
2. Closing the window hides it to the tray, and processing continues.
3. To stop: tray icon → **Quit** (a graceful stop). **Pause & release GPU** frees the computer without quitting.
4. Updates: **Check for updates** in the header. This works in-app from 0.2.4 onward; 0.2.2 and 0.2.3 needed a manual install.

### Lean build path (Sergei 2026-10-15)

Sergei: "go as lean as possible." The held supervisor, per-run frozen graphs, guardian/Job/seal wrappers and freeze manifests are dropped from the build route (their source stays in `scripts/packaging/` and their evidence in `scratch/`, unused).

1. Bump `VERSION`, `package.json` and `package-lock.json` (Sully).
2. From the checkout root, run `npm run pack` (same as `node scripts/build-installer.cjs`). It takes about 3–4 minutes and works offline.
3. The installer lands in `dist/Comic-Metadata-Setup-<version>.exe`, with `latest.yml` and `.blockmap` next to it.
4. The run ends with `BUILD OK <path> <bytes> sha256 <hash>`. Anything else means the build failed: the driver exits 1.

How it works:
- **Inputs.** Reproducible from committed pins, independently of the old recovery folder:
  - Prerequisites: Windows x64, Node **26.12.1**, npm **11.20.0** beside Node. `package-lock.json` pins the dependency tarballs by SHA-512; `scripts/packaging/toolchain-lock.json` pins Electron 43.7.9, NSIS 3.0.4.1, NSIS resources 3.4.1, rcedit 2.6.0 and the extraction binary. `runtime-lock.json` pins Python 3.14.8, 7-Zip 26.04 and every wheel by SHA-256.
  - Explicit online preparation: `npm run prepare:runtime` creates `build/toolchain/`. Optional `-- --output <fresh-directory> --cache <download-directory>` selects other locations. Downloads are authenticated before extraction; npm lifecycle scripts stay disabled, and npm's cache/config/temp files stay in the selected workspace. Neither the 7-Zip installer nor the NSIS uninstaller stub is executed.
  - The input contract is `native/`, `capsule/runtime/`, `dependencies/node_modules/` and `toolchain-manifest.json`. The manifest is published last and records every file and directory plus the source pins. Missing, altered or extra files fail verification. An existing output is never overwritten; `npm run prepare:runtime -- --verify --output <directory>` checks it without downloading. A package version bump alone does not invalidate matching dependency contents.
  - Build offline with `npm run pack`, or `npm run pack -- --inputs <prepared-directory>`. A clean checkout receives the prepared dependencies; an existing `node_modules/` must match the manifest. The build never downloads missing inputs.
  - Test Python is `<prepared-directory>/capsule/runtime/python/python.exe`; test 7-Zip is `<prepared-directory>/capsule/runtime/7zip/7z.exe`. Run preparation/build through the studio's reviewed owned-process route with a **600000 ms total deadline**; no duplicate run on a timeout.
  - Preparation proof (2026-10-28): all eleven upstream archives were freshly downloaded with matching pins, and the assembled Python imported SQLite, Pillow, Playwright, greenlet, pyee and typing_extensions. The final input readback passed: 442 native files, 468 runtime files and 7,589 dependency files; both existing safe NSIS source pins match. Preparation contract tests passed **6/6**, including tampered cache/tree, missing completion marker, existing-output refusal and CRLF-independent source pins. A first attempt hit Windows `EPERM` while renaming `node_modules` after tool execution; publication now writes the completion manifest last without moving executable trees. Failed attempts remain evidence and cannot be consumed by the build.
  - **Migration complete (2026-10-28):** the corrected 0.6.0 candidate at `e21e0fcdab7227fa58a367301019123c56628153` built from fresh inputs with no pre-existing `node_modules`. Futaba verified the unmodified packaged 0.6.0 app in a private offscreen profile and its actual tray Quit path (normal exit 0; all 620 package hashes unchanged). Only after that proof, the supported studio sweep removed `scratch/cmo-packaging-recovery-20261015/`: **8,717 files / 878,563,659 logical bytes**, with target absence verified. The new input manifest and qa-040b/qa-050c ownership evidence remain. Exact build, smoke and cleanup records: `Docs/ComicsMetaOrganizer_DevHandoff_v0.6.0_2026-10-28.md`; historical recovery inventory: `Docs/ComicsMetaOrganizer_ScratchRecord_2026-10-24.md`.
- **Staging.** The driver stages `build/staged` (runtime, engine sources, licences) and its manifest.
- **Build.** It runs electron-builder in a child process, `scripts/packaging/build-lean.cjs`. `node_modules/`, `build/` and `dist/` are gitignored.
- **Uninstaller stub (hard rule, kept).** The generated NSIS `BUILD_UNINSTALLER` stub is never executed. The pinned safe route (`nsis-safe/`) extracts the uninstaller with the pure-JS decoder and checks it byte-for-byte against upstream's pure `UninstallerReader`.
- **Path guard.** makensis 3.04 is not long-path aware, and the old held build failed at a 264-character include path. `nsis-path-bound.cjs` refuses any NSIS input or output over 254 characters before compiling. From this checkout the longest path is 228.
- **Exit codes.** electron-builder's exit hook can turn a failure into exit 0. The child keeps exit 1 on failure using upstream's `process.on('exit')` pattern, and the driver treats exit 0 as success only with the child's final `leanBuild` receipt and matching installer bytes.

Install/QA note: the installed tree goes 142 characters deep below the install folder. Keep any private install folder at or under about 100 characters.
- Release: Sully synchronizes `VERSION`, `package.json` and `package-lock.json`, commits and pushes immediately. `npm run release` promotes the exact QA-certified artifact bytes from its pinned release contract, verifies the named tag and retains the last four heavy GitHub releases; it never rebuilds the approved installer. No public installer release until actual native installation/update QA and independent review pass.
