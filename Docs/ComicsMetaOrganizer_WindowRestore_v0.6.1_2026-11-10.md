# Window restore at fractional Windows DPI — 0.6.1

Retry07 proved a real restore defect: settled old outer/normal bounds and saved JSON were `{x:40,y:40,width:900,height:600}`; the new instance and saved JSON became 902×602 on the same display at scale 2.5. Content grew from 888×565 to 890×567. Minimum stayed 640×480; the display/work area and maximized=false state were unchanged. This was not an immediate measurement or a minimum-size clamp. Original guest evidence remains under `scratch/install-update-061-20261110/retry07/output-processing/update-result.json` and Futaba's retained QA evidence.

Electron 43.7.9's Windows constructor applies explicit x/y using SetPosition twice. SetPosition obtains the current size and passes it through SetBounds, introducing repeated size conversions. [Exact constructor and setter source](https://github.com/electron/electron/blob/v43.7.9/shell/browser/native_window.cc#L159-L166), [setter implementation](https://github.com/electron/electron/blob/v43.7.9/shell/browser/native_window.cc#L257-L258). Upstream documents outward rounding and cumulative size drift on fractional Windows scales; its proposed engine fix is still a draft. [Issue 55245](https://github.com/electron/electron/issues/55245), [draft 55429](https://github.com/electron/electron/pull/55429).

The app previously relied solely on constructor options to restore the saved normal outer DIP rectangle. It now reapplies that validated rectangle once using setBounds after construction, before maximize/show and persistence handlers. Constructor x/y remain present to select the proper monitor's DPI. There is no pixel subtraction, tolerance, resize loop, content-size substitution, dependency upgrade, or change to user resizing. Default/invalid-state and non-Windows behavior stay unchanged.

Approved contract: DesktopShell UX spec (2026-10-12), window section: normal outer DIP bounds, 640×480 minimum, valid connected-display guard, getNormalBounds persistence with 400 ms debounce, and normal bounds before maximized restoration.
