## Findings

### Blocker

None.

### Major

- **M1. In QA mode the tray icon and tooltip are identical to the real app's, so a visible QA instance misleads Sergei.** Reported by Jane during the pass: Sergei saw two "Comic Metadata — Processing enabled" tray icons, took them for two copies of his app and quit both, which stopped his real app (he restarted it at 09:56). My first QA instance had already been quit this way once and I restarted it (09:58), which put the second icon there. The window is hidden but the tray icon is not. Repro: launch `dist/win-unpacked` in private QA mode beside the installed app; two identical tray icons. It is a shell behaviour (`desktop/main.cjs`, unchanged since 0.2.5, so not new in this release) and it is reachable only through the QA environment variables, never in Sergei's normal use, so it **does not gate this release**; it is rated Major because it caused a real interruption of his running app and breaks the rule that our tooling must not intrude on his machine. Suggested fix (Ender's call): in QA mode give the tray a distinct tooltip ("Comic Metadata (QA test copy)") or no tray icon at all.

### Minor

- **m1. Page copy for a partial `writing` answer is unreachable in practice.** "Deleted {d} of {total} files. A comic in this folder is being written now, so nothing was requeued…" can only come from a guard lost after the first delete, but the route takes every comic's guard before the first delete and holds it to the end. I verified the sentence by stubbing the server's answer and measured it in layout; no real repro exists. Not a defect, a note.
- **m2. A damaged comic with a different-version backup gets the `backup` wording, not the `comic` wording B6 gives for "damaged".** Repro: the 0.2.5 M1 shape 3 (a skipped comic that fails the zip test, with a good older backup; the plan was recorded after the damage, so the comic matches its recorded state). Rows: "Failed the zip test. The archive is damaged." and "A recovery backup is kept. It is not a copy of this comic, so it may hold another version. Decide in Kept backups." B6 lists "damaged" under `comic` ("Do not delete it until the comic is checked", because the backup may be the only good copy). The cause is that `prove()` ignores the zip failure when the plan itself holds the damaged bytes. No offer is made and nothing is deleted by the app; the damaged row sits directly above; but "Decide in Kept backups" invites deleting the only good copy. Suggest: a `zip_failed` comic always gets `unproved: 'comic'`.
- **m3. A case variant of the temp name is treated as the app's own.** `{comic}.METADATA-TMP` is offered and deleted, and its row prints the lowercase name. On a case-insensitive Windows folder it is the same name, the app never writes a capitalised one, and no content is read, so the risk is nil; but B2.3 says "exactly". Nit.
- **m4. Wording for a non-file at the temp name.** A junction or a folder named like the temp file is listed as "A leftover temporary file is next to this comic: …" with no offer and the generic "Fix them, then check again." Nothing says why there is no offer. Nit. The same with a held write guard: no offer, no mention that a comic is being written (spec'd: B2.4 says no offer; the page says nothing more).
- **m5. After a partial delete the list is a snapshot.** The row of the temp file already deleted stays (offer cleared) until the next Check (0.2.5 m9, as specified for A6).
- **m6. `temps: null` is read as an empty list** (answers `changed`, nothing deleted) while `temps` as a string answers `invalid`. Harmless nit.
- **m7. Page overflow at 320 CSS px** is the Live library path (`#roots`, 135 px over with or without cards; the fixture library path is 65 characters). Pre-existing, not cards (pattern alert P3).
- Not re-examined and unchanged: 0.2.5 m2 (what Sergei sees on a real interruption: **the leftover temp file no longer blocks the offer, which closes A9**), m5 ("due" means the comic records), m6 (an open ticket with an unreadable plan stops folder passes), m10.
