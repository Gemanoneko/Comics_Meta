## Entry boundary and evidence

Actual QA begins only on a committed build or immutable pinned snapshot. Receive Ender's fresh protocol2 qa-handoff receipt, re-run the identical declared invocation through its separately cleared execution graph, and paste both identical canonical receipt lines into the versioned QA report. Stop on different source/version/runtime/harness/dependency identities, dirty-state discrepancy, added/removed input paths, missing script, unknown command scope or missing ownership proof. The graph must cover setup plus execution under one total600000ms deadline, native exit statuses and owned descendant closure; do not silently retry a rejected or timed-out run.

Use owned scratch state, profile, library, locks, logs, temp and non-live port; no live checkout/state, real keys/comics/providers/GPU or signed-in browser. Fixture archives and provider/feed responses are synthetic and offline. Do not import the running v0.1.4 library or retire its scheduled task. Installer/update tests require real packaged artifacts and isolated installed copies, with exact prior and next versions, hashes and signed-off feed metadata. Mocks support targeted branches but never prove installed prior→new replacement/relaunch.

Evidence per run: exact versions/commit and complete path+byte manifests before/after; reviewed graph identity; native/root/owned descendant results and elapsed time; measured UI results; actual archive diffs/read-back/manual ledger/backup disposition; safe nonsecret state comparisons. Expected archive differences are listed individually; unrelated fields and other Web entries are compared exactly. Secret comparisons remain private sentinel checks; never paste key values into reports. All rows below are pending until actual evidence is filed.
