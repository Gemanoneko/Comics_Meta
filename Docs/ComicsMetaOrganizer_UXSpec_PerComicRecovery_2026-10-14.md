# Per-comic recovery — failure-filter amendment

Date: 2026-10-14. Owner: Judy. Status: reviewable; Sully commits before implementation. EXTEND the five failure filters and existing Details dialog. Sergei requests meaningful options for each comic needing help, visible competing identities, and useful dead-link recovery. Supersedes FailureFilters §4.1 dead-link/conflict guidance and §4.3 Details block; other filter precedence/counts and existing one-attempt retry decision stand.

Basis: NN/g visibility, recognition over recall, error prevention and recovery; Jakob (existing Details/dialog/form patterns), Hick (one decision at a time), WCAG2.2 AA. Ender's bounded read-only intake confirms current search/issues/preview/apply fills empty fields and cannot resolve nonempty identity/Web; new guarded preview/confirmation routes are required. This spec does not pretend existing Approve resolves a conflict.

## 1. Entry and layout

Keep the list and chips. On stopped rows retain Try again. Dead/conflict rows add **Review options** (tooltip: “Compare this comic's identity and review ways to fix this problem.”), in-flow below reason, same32px row-button treatment. Opens the existing Details modal with focus on the new problem heading (tabindex−1); its content begins before optional manual lookup. Details also opens this section for every problem, including held/failed. Plain nonproblem Details stays unchanged.

Heading **Help with this comic**. Show badge, concise specific cause, current local cover (existing), filename/path (existing) and action options below. No second modal or banner over the comic. Long evidence wraps; no horizontal scrolling. Two identity cards side by side only where space permits; stacked, always file first, at narrow widths. Cards are ordinary labelled sections, not clickable containers. Each action has an actual button. No preselected identity or default destructive choice.

## 2. Conflict: show between what and what

Row: “The file says {fileSeries} #{fileNumber}; ComicVine link {id} says {cvSeries} #{cvNumber}. Review options to choose the correct comic.” Never display an invented placeholder as evidence; if values missing: “This file's identity does not match its ComicVine link. Review the available evidence.”

Details cards:

| Card | Required visible evidence |
|---|---|
| **In this file** | Embedded Series, Issue, Year, Web link; missing value = “Not recorded”. Separately labelled filename identity if it differs, never presented as embedded metadata. Local cover is labelled “Cover in this file”. |
| **ComicVine link** | Series, Issue, Issue date (or “Not available”), volume name/start year/id when available, issue id and safe provider page link. Candidate cover labelled “ComicVine cover”; it is evidence, not proof. Show “Saved result — checked {local date/time}” or “Checked just now”; outage must not masquerade as current verification. |

Below: **Differences** listing every disagreeing identity field with actual values: e.g. “Series: Good → Another Series”; “Issue:1 →7”; dates alongside, not hidden. Example fixture: file Good#1 versus ComicVine issue123 Another Series#7; title alone cannot identify editions. Dates and sourceids remain visible even when identical. A missing date is explicit, never guessed.

Actions:

- **The file is correct**. Tooltip: “Keep this file's identity and find a matching ComicVine link, or remove the incorrect link.” Opens inline choices **Find a matching issue** and **Remove this ComicVine link**. It does not resolve anything by clicking the first button. Match search prefills current Series/Issue; show editable search inputs and edition/year/id evidence for results. A chosen verified matching issue opens consequence preview: replace only this ComicVine Web entry, keep Series/Number/Year and other metadata. If provider identity still conflicts, report “This issue still differs from the file. Choose another issue, or review the ComicVine identity option.” Do not relabel the conflicting result a correct match.
- **The ComicVine issue is correct**. Tooltip: “Review the identity fields that would change to match this ComicVine issue.” Opens guarded consequence preview with exact differing Series/Number and date fields only where actual trusted evidence exists, plus canonical ComicVine link if needed. All other metadata stays. No replace of synopsis/credits/publisher/other populated fields as a side effect. Letter-case-only and punctuation-only differences retain the existing spelling under Sergei's earlier rulings; this action addresses a substantive identity conflict. If evidence insufficient, unavailable state explains which identity values cannot be checked and offers search/recheck, no confirm.
- **Find another issue**. Tooltip: “Search ComicVine and review another issue before changing this comic.” Shared search/result flow; selecting a candidate alone never writes. If it differs substantively from the file, offer the same explicit keep-file/use-provider decision with the new candidate. No automatic broad metadata approval.

Removal is explicit and local: preview identifies the exact ComicVine Web entry to remove; retain all other Web entries and embedded fields. Explain: “This link will be removed. The file's identity stays. Automatic research may look for a matching issue again.” No persistent ignore/mute decision is introduced. Removing the conflict link can clear this particular problem only after verified write/classification, not by hiding its row.

## 3. Dead link

Row: “ComicVine returned Not found for linked issue {id}. Review options to replace or remove this link.” Use this definitive sentence only for recorded Object Not Found; temporary outage remains held, never dead.

Details shows exact embedded Web value, dead issueid, observed checktime if available, file identity/year/cover and “The link no longer identifies an available ComicVine issue. Your other metadata is still in the file.”

Actions **Find a replacement link** (tooltip: “Search for the correct issue and review replacing only this ComicVine link.”), **Enter a ComicVine issue link** (tooltip: “Check an issue link before reviewing a replacement.”), **Remove this ComicVine link** (same guarded explicit removal as §2). Link entry label **ComicVine issue link**, helper “Paste the issue page link. The app checks it before any change.” Button **Check link**, tooltip “Fetch this issue's identity; nothing is written.” Ender restricts to supported ComicVine issue URL/id forms; no arbitrary URL fetch. Invalid: “Enter a ComicVine issue page link.” Notfound: “ComicVine could not find this issue. Check the link or search by series.” Valid preview shows both identities; disagreement returns to §2 choices. No replacement based on HTTP success alone. Existing nonComicVine URLs remain.

## 4. Writes stopped / failed / held

Stopped: reason, attemptcount/limit and raw last error (existing300char bounded text), plus “Close any program using this comic and check that you can save to its folder. Repair or replace a damaged archive before retrying.” Do not diagnose locking from access-denied alone. **Open folder** tooltip “Open the folder containing this comic so you can check or repair the file.” **Try again** retains exactly one attempt and failurecount; success means scheduled, not written. Pending “Retry requested”; helper “One write attempt will run when this folder is checked. A failure stops it again.” No automatic restart of five attempts.

Write failed: show attempt/retrytime, raw error, **Open folder** and **Refresh status** (tooltip “Read this comic's current status without starting another write.”). “The app will retry on its own. You can check the file while it waits.” No bypass of backoff or second retry button. A stopped transition offers stopped actions.

Held: describe structured cause and honest nexttrytime; no Retry that bypasses provider quotas. Missing key offers **API keys** only inside the shell, opening the existing approved setup/settings keys surface with focused ComicVine field, tooltip “Open API key settings; no comic metadata changes.” Browser fallback explains use app settings, not invented browser key editor. Rejected key: “ComicVine did not accept the request. Check your key in API keys.” Quota/cooldown/unreachable/empty: explain current wait, **Refresh status**; no unnecessary user fix, no forced request. Preserve held-line quietness in All files; Details still explains it. This action opens the narrow keys-only editor in §4a, not the single-use first-run setup.

Library, source settings and processing state stay as they are.” Secondary **Cancel**, tooltip “Discard unsaved key entries and return to this comic.” Every input/show control retains the approved first-run tooltip, except blank-input wording says “Leave empty to keep the saved key” when one exists. ## 5. Consequence preview / confirmation / response

Inline, under chosen option: heading **Review this change**; a field table **Field / In the file / After this change**, sourceissue/volumeid, evidence timestamp, and “Only these fields change. Other metadata is kept.” Removal uses explicit “Remove” in After; no em dash that hides its meaning. Show exact embedded values safely as text, including every affected Web entry. Unchanged identity values remain in evidence above. Preview bound to the current file/record and trusted provider response. No write on search/selection/preview/Cancel.

Primary button **Save this change**; tooltip “Write only the changes shown, then verify the comic.” Secondary **Cancel change**; tooltip “Discard this preview without changing the comic.” Confirm is visible only for a complete valid fresh preview, never the dialog's Enter-default. Clicking opens inline final confirmation “Save these {n} changes to {filename}?” with **Save and verify** (tooltip “Save the listed fields using a recovery backup and verify the result.”) and **Go back**. Removal says “Remove this ComicVine link from {filename}?” No global confirmation modal. Focus starts on Go back; Esc returns from confirmation to preview before closing Details.

Saving: disable change/search/close controls that could invalidate the active write; button **Saving…**, live polite status “Saving this change and verifying the comic…”; do not offer Cancel midwrite. Escape cannot imply cancellation. On verified success “Change saved and verified.” Show updated identity/problem status and refresh counts/list. Backup deleted/retained copy uses actual backendresult; retained recovery backup never treated as an error or automatically removed by this flow. On failure “The change was not verified. {safe actionable reason}”; show truthful backend write/recovery result, never assert unchanged unless proven. Keep evidence and retry/error context. On stale archive/provider/plan: “This comic or its evidence changed. Review the updated values before saving.” Fetch new preview; confirmation revoked. While paused: keep read-only evidence, disable write actions with visible “Processing is paused. Resume processing before saving a change.” Never secretly resume. Quota/providerfailure during preview: visible wait/recheck guidance, no confirm based on old fields. Doubleclick produces one operation.
