# Automatic metadata sources

Since 2026-10-12, general free web search, Wikipedia/wiki leads, re-fetching already rejected saved leads, GetComics and PREVIEWSworld are switched off by default (`"sources": {"disabled": [...]}` in `config.json`; `[]` turns all back on), and Yandex is no longer one of the regular engines. The paragraphs below describe the kept code. A switched-off source is skipped on every pass, including during an identity conflict, a hold or a dead ComicVine ID (§ ComicVine identity check). The sources still on keep their strict verification in those cases: the Dark Horse and Image catalogs, the publisher lookup, and saved and Lens leads. A saved lead rejected under strict verification is fetched once more after the comic leaves that state, because the hinted-publisher route may accept it then.

Regular free web research tries the same `series #issue comics` query (`series comics` for an unnumbered book) through DuckDuckGo and then Bing. Yandex, the former third engine, is kept in code but not searched, and its verification action is hidden. Each uncached attempt obeys the same shared budget and pacing; fallbacks cannot issue an immediate second request. Cover hints and all issue/publisher/year/cover verification remain in use. Engine misses keep the ordinary comic backoff; deployment does not reset earlier research signatures or future miss deadlines.

Bing renders its ordinary organic result cards and decodes only bounded `www.bing.com/ck/a` base64url targets. Ads, navigation, internal-engine links, malformed encoding, credentials and obvious nonpublic destinations are excluded. The existing public-address DNS and redirect checks still guard actual source retrieval, and publisher request limits still apply. Browser profiles (`ddg-profile`, `bing-profile`, `yandex-profile`), result caches and saved holds are independent. Existing DDG/Bing cache keys and hold rows are retained; Yandex uses a distinct key and hold row. All engines share the existing300/rolling-24-hour reservation ledger, minimum120-second spacing and an actual browser-navigation timestamp fence. The fence accounts for slow browser startup without adding another quota charge. Lower configured caps and longer spacing win. A Yandex human hold does not permanently pin other engines: DDG/Bing can be reconsidered at the comic's already-recorded deadline. Actual challenges stop their engine without solving, stealth, proxies or cookie transfer.

Yandex uses `https://yandex.com/search/?text=...`, with no API or paid integration. Genuine challenges expose a separate **Open Yandex verification** action. One explicit click queues one owned window in the metadata worker; it waits for the current operation, shared budget, navigation pacing and ordinary longer holds. No dashboard poll, startup or Resume opens a window. The user completes the challenge; the app only observes a normal, matching query with usable rendered results. It then closes the dedicated persistent profile and reports that closed lifecycle. Cookies remain in that profile; no signed-in browser, Lens profile or copied session is used. A later natural request can still challenge again. Global Pause and server/worker restart cancel visible intent without clearing the challenge. Closure must be established before success or pause acknowledgment. Lens's separate verification action is unchanged.

The Yandex normal-result selector is deliberately narrow and fail-closed. Offline organic-card fixtures validate query binding, visible text, ad exclusion and unknown-page rejection. A normal live Yandex results DOM was unavailable during implementation because the reference browser received a challenge; live markup compatibility and sustained challenge-cookie acceptance are not claimed. Unknown empty-page markup is treated as unavailable rather than cached as a successful empty response. No activation probe or quota reset is performed.

Search capture waits for the requested query to appear in a visible search field and accepts only visible organic links with nonempty rendered titles. Hidden cards, stale query pages and unrendered results are diagnostic failures, not claimed human challenges or successful empty searches. Old Bing cache entries containing blank or malformed titles remain stored but are not used; any replacement still waits for existing holds, pacing and the shared daily budget. Valid cached results and explicit empty-result responses remain usable. Offline fixtures establish this capture contract; they do not prove live provider availability or that a search result will pass comic verification.

Free search now renders the ordinary `https://duckduckgo.com/` results page using the already installed Playwright/Edge runtime. The primary text query is the unquoted series title, `#issue` and `comics`; publisher/year remain mandatory identity checks on retrieved pages where available, rather than search restrictions. Only organic result-title links are inspected (at most five); series pages and search snippets cannot authorize writes. Direct publisher page requests still obey their publisher budgets.

The metadata worker alone owns a dedicated persistent `data/ddg-profile`, separate from Lens, Chrome and Codex's browser. Each search closes its browser context and driver on its owning thread; profile ownership stays locked until descendant closure is verified. An unnamed Windows kill-on-close Job is held for that metadata process's lifetime, never closed while the worker remains alive. Unsupported ownership or uncertain cleanup fails closed. Pause acknowledgment happens after browser closure. The existing 300/rolling-24-hour trial cap, 120-second spacing, cache-first behavior, ledger, source retries and longer saved holds are retained. There is no stealth, challenge solving or cookie transfer. A challenge retains a cooldown; this change adds no DDG human-resume UI. A normal results page in another browser does not clear the application's saved hold.

Wikipedia discovery ranks comic articles ahead of matching film/TV titles within the existing three-candidate response. Its first two articles still supply at most eight inspected leads; generic search-footer links are skipped and specific issue/product URLs are prioritized. Articles and snippets remain discovery hints, with unchanged exact issue/publisher/year and cover verification before metadata use.

Wikipedia HTTP 429 now saves a provider-wide deadline from Retry-After (seconds or HTTP date). Missing/invalid Retry-After uses the existing one-hour first-error delay. Observing a hold does not extend it, a longer saved hold wins, and seven-day cached API responses remain usable before the network hold check. Wikipedia retries remain independent of DuckDuckGo/vendor holds and normal comic retry clocks are retained; no deployment-wide reset occurs. DuckDuckGo human challenges remain held, never bypassed.

General free web search and Wikipedia/wiki references have independent per-source retries. API, catalog and cover-search waits do not disable these fallbacks; a thin API issue without synopsis text can also use verified free evidence. Legacy research checkpoints keep their normal retry until their next due pass, rather than being reset on deployment. Search explicitly uses the existing free route, never a paid search vendor. Wikipedia discovery can continue while ordinary free search waits, but a series article remains a lead and cannot authorize issue metadata.

Free browser searches and app-initiated Yandex verification navigation use a combined application trial limit of300 requests per rolling24hours, at least120seconds apart. These are cautious application bounds, not a published provider allowance or a guarantee against challenges. Internal `free_daily_request_limit` can lower the300ceiling and `free_min_interval_seconds` can increase the120second minimum. Pacing returns a saved-ledger/navigation deadline without sleeping the metadata worker. Cached queries consume neither requests nor spacing; seven-day caches and existing challenge holds are retained. Failed admitted attempts remain conservatively counted.

The original shared web request ledger is preserved without resetting historical usage. All web requests still count conservatively toward each applicable cap: the free route uses its 300 ceiling, while optional Brave retains the existing `daily_request_limit` (100 by default), three-second spacing, its own hold and provider/account limits. No vendor billing allowance is increased. Exact issue/publisher/year checks, cover checks on saved leads, synopsis review and archive verification are unchanged. Exhausted or challenged sites are not bypassed through a free result link.

Metron, GCD and Google Books are connected to automatic discovery. Credentials remain in the configured `.env`; dashboards, request errors and cache keys exclude secrets.

- Metron: exact series, issue number and cover year, unique result, local/remote cover agreement.
- GCD: exact series and number plus cover agreement; check the key date when present. If a cover cannot be retrieved, no identity-dependent write is made.
- Google Books: graphic novels and collected editions only. Match an existing ISBN, or an exact title and matching cover; reject ambiguous results.
- Open Library: local dump index, exact ISBN matching. This avoids bulk API harvesting. The dashboard reports that bulk data is required until an index exists.
- GetComics: metadata-only fallback after database sources. A shared SQLite gate permits at most one uncached HTTP request per five minutes across workers and restarts, including followed pages and redirects. Search results and source pages are cached for seven days. Exact issue checks or exact book title/year/known publisher checks must pass before synopsis review; ambiguous candidates are rejected. Human verification and access failures stop further site requests and are shown on the dashboard. No challenge bypass or comic-download links are used. Contact the assistant after manually verifying access to arrange a controlled retry.

New descriptions pass the existing quotation, claim and spoiler checks before being queued. The serial writer verifies metadata and archive page integrity before removing a full backup. Existing populated fields are retained by these fallback connectors, except values the in-book tiers wrote (§ Replacing in-book values).

GCD uses a conservative application budget of 1,000 requests per rolling day; Google Books uses 500. Both cache successful responses for seven days and honor server retry delays. Metron reads the server's burst and sustained quota headers.

## Open Library local data

Download a works or editions dump from https://openlibrary.org/developers/dumps when sufficient temporary space is available. From this folder, run:

```powershell
python open_library.py "D:\Downloads\ol_dump_editions_latest.txt.gz"
python open_library.py "D:\Downloads\ol_dump_works_latest.txt.gz"
```

The importer streams compressed data and retains only current catalog title/ISBN matches in `data/open-library.sqlite`. It does not decompress the whole dump. Import editions and works for edition identification plus work descriptions. Source dump files are not deleted by the importer. Re-import when the catalog expands; no dump has been downloaded automatically.

## Lead resolution and cover research

Saved web results and relevant Wikipedia external references are followed automatically. Unrelated wiki hits are discarded. Issue identity checks reject wrong issue numbers and Reddit-only identity claims. A numbered comic always needs its exact `#N` issue number in the page title. Saved, Lens and web leads may confirm any publisher and unnumbered books (one-shots, graphic novels, collected editions) when all of these hold:

- **Exact title.** The title may stand beside site names, a year or a book format word (TPB, HC, graphic novel, one-shot). A title segment that adds issue, part, volume, chapter or spelled-out numbering ("Book Two"), or names a series, omnibus, absolute or deluxe edition, review, character page or another medium, never matches. Any other segment counts as a site name, so a subtitle of a different book ("The Sandman - Overture | DC") is not yet told apart. A year range such as "(2018 - 2021)" and series URLs (`/series/`, ComicVine volume pages) mark series pages and never match. A numbered issue title never matches an unnumbered book.
- **A whole book.** A file without an issue number is not assumed to be a book. It qualifies when the file says so (ISBN; TPB, HC, omnibus, one-shot, GN or graphic novel in its path; a book `Format`; `Count` 1), when the page calls it a one-shot, or when the page names a collected format and the archive has at least 48 images.
- **A known creator, named in full.** Embedded Writer, Penciller, Inker, Colorist, Letterer or CoverArtist credits (not Editor), or credits read from the cover that look like a person: not the title, a publisher, a company, a place or a cover blurb ("Eisner Award Winner"). A character name that reads like a person ("Bruce Wayne") is not yet told apart. A leading "Art" stays a first name (Art Spiegelman), "Surname, First" is one person, and accents are ignored on both sides.
- **Any known year**, and **an agreeing cover**. A candidate cover that cannot be downloaded or decoded counts as not agreeing for that page; it never stops the lookup and never blocks a provider. Near-blank covers never agree.

The established route, a hinted publisher named on the page, is unchanged. A publisher is written only when the page names the whole publisher: a known publisher (Image, Marvel, DC, Dark Horse, BOOM!, IDW and others) under its canonical name when a distinctive phrase such as "Image Comics" appears, any other multi-word name as read when the page names it in full rather than as part of a longer name. A one-word or partial cover reading ("Dark", "Image") is never written on its own. An empty issue number is never written. Search or cover matches alone never authorize writes.

A comic whose ComicVine issue disagrees with its embedded series and number is an identity conflict. § ComicVine identity check below describes it, together with the hold and the dead ID.

Cover verification compares layout and edges to tolerate scan brightness, in addition to the existing pixel check. Fractional issue numbers remain distinct.

Unresolved cover searches are persisted in the catalog. A supervised project-owned browser worker uploads covers to Google Lens independently of the chat, with a dedicated profile, pacing and daily limits. An unsolved human check holds Lens for an hour; a solved one for 5 minutes, growing to 10, 20, 40 and 60 when checks return within two hours of the previous solve (`lens_verification.solved_hold`). Human-verification pages stop browser searches and surface a dashboard action; the user completes verification in a dedicated window. Lens candidates enter the ordinary verifier and do not directly authorize writes. General free search can still be blocked or capped.

70 automated checks passed after adding browser queue exclusivity, persistent request limits, stale-archive rejection, safe result extraction and key-redacted API errors. A real browser cover upload reached Google Lens and encountered a human-verification page, correctly reported without attempting to solve it. A real SerpApi fallback for Lady Death - Sacrilege #2 returned six candidate links and persisted them for ordinary verification; these search results alone did not trigger an archive write. (The SerpApi fallback was removed on 2026-10-16.)

## Provider waits and research priority

Dark Horse and Image use their public catalog searches; PREVIEWSworld uses targeted web-search results and accepts only product catalog pages. No accounts or credentials are used. Each catalog has a shared 300-request rolling daily budget and five seconds between uncached requests, including redirects; pauses interrupt pacing. Search results and product evidence are cached for seven days. Site challenges stop requests and other access failures cool down for one hour. Verified issues require exact series/number, available release year and cover agreement. Collected editions require exact volume/title, available release year and existing ISBN agreement or matching cover. Only missing publisher/identity fields and reviewed synopsis evidence are supplied; variant credits and unverified edition details are excluded. A synthetic match check is not a demonstration of a live archive write. PREVIEWSworld was inaccessible in the initial live probe and remains subject to public-web search availability.

Provider-wide request budgets, verification blocks and service outages are recorded separately from comic-specific errors. They retain the normal research retry (one day for unresolved identity, 30 days for current verified identity), rather than shortening it to an hour. The exception is a comic held for its ComicVine identity check, which follows the hold retry in § ComicVine identity check. Actual per-comic errors still use the shorter retry. Cached responses remain usable before provider cooldown checks. A one-time migration repairs old GetComics-only hourly retry records without changing comic archives or hiding other errors. Within each folder, unresearched comics are preferred, followed by verified source leads, then unresolved retries. A ComicVine connection failure, rejected access or server error starts a shared five-minute pause instead of being repeated for each comic, and an HTTP 429 rate limit a one-hour pause. An "Object Not Found" answer starts none.

## ComicVine identity check: conflicts, holds and dead IDs

ComicVine is searched only by the issue ID in a comic's embedded `Web` link (`.../4000-N/`). A comic without one is never searched on ComicVine. For a comic with one, ComicVine is also the identity check. Metron is asked first when it is on and due. ComicVine is then asked for that issue, from its 30-day cache when it can, even when Metron or saved evidence already answered. It is skipped only when saved evidence already carries that same matching issue. Its answer decides what may be written:

- **It agrees** (same series and number as the embedded `Series` and `Number`). Empty fields are filled: from Metron when Metron answered, otherwise from the ComicVine issue.
- **It names another series or number: an identity conflict.** No metadata field is written, from new or saved evidence. Every other source is still searched, with strict verification: a web page needs a known creator named in full and an agreeing cover, even when it names the hinted publisher. Catalog providers such as Metron and GCD keep their own checks. Only an empty Summary can still be filled, from a source that verified the embedded series and number. The conflicting issue is saved with the comic's research record, so later passes keep the conflict even when ComicVine cannot answer. The comic counts as unresolved (`identity_conflict`).
- **It cannot answer: a hold.** This covers an outage, a pause, the hourly budget, a rate limit, a missing `COMICVINE_API_KEY`, or an answer that names no issue. If no conflict was saved earlier, the comic is held and no field is written, Summary included. It stays `needs_identity_lookup`, and evidence found meanwhile is kept for the pass after ComicVine answers.
  - **First held pass.** Every other source is searched once, with strict verification.
  - **Later held passes of the same archive.** Only ComicVine is asked again: no source searches, approved-list cover hash, local-model cover read, lead downloads or Lens task. New cover leads still get one strict check.
  - **Retry.** Never before ComicVine's own wait ends (about 5 minutes after a pause, an hour for the comic whose own request failed). Otherwise 5, 10, 20 and 40 minutes, then hourly. A missing key has no known end and keeps the daily retry.
  - **Recovery.** As soon as ComicVine answers any request again, every comic held by a ComicVine wait that has ended is checked at its folder's next pass. A hold with no known end (a missing key, or an answer that names no issue) keeps the daily retry.
- **It reports that the issue does not exist: a dead ID.** ComicVine's "Object Not Found" (status 101, also as the body of an HTTP 404) is an answer, not an outage. It starts no pause and is cached for 7 days. A conflict saved earlier still blocks. Otherwise every source that has a strict mode is searched strictly and may write: the publisher catalogs, the publisher lookup, saved and Lens leads and, when switched on, GetComics and general web search. Catalog providers keep their own checks, and Sergei's approved exact-cover list still counts. Evidence saved on earlier passes is not written for a dead ID. The `Web` link itself is never rewritten. A corrected `Web` link is checked at once; an issue that ComicVine restores under the same ID stays hidden for up to 7 days.

The in-book tier never writes a comic whose `Web` names a ComicVine issue, or a comic recorded as an identity conflict (README § Local model). Each hold, dead ID and conflict saves its reason as `detail` in the comic's research record, and structured fields the dashboard reads: `dead_link` (the issue number ComicVine reported missing), `hold.next_try_at` (the held comic's next try, the record's `retry_at`) and `hold.cause` (`cooldown`, `limit`, `unreachable`, `rejected`, `empty` or `no_key`, from the request that could not be answered), and for a conflict `conflict_file` (the file's series and number) with a `detail` that is word for word the dashboard's sentence. The dashboard lists them under its Status filter (README § Automatic processing).

## Replacing in-book values

Sergei, 2026-10-13: outside sources may replace in-book values when they disagree. Before, a verified source filled only empty fields, so a wrong in-book value stayed.

- **Which values.** Only a value the in-book tiers wrote (history source `in-book:cover`, `in-book:filename-number` or `in-book:credits`) and nobody has changed since. The catalog's write ledger (`write_ledger`, one row per verified write, in the same transaction as its history row) records the fields each write set, whether the service or Sergei started it, and the archive's size and modification time before and after. A value stays in-book only while the archive has changed through the service's own automatic writes since: each started from the archive the one before left, and the last left the archive the folder scan read. A manual write (the dashboard, a reviewed reference batch) or another program saving the archive ends that, for every value then in it, even one that still reads the same. A value Sergei or another program wrote is never replaced.
- **Which sources.** Any source whose result already authorizes a write here: Metron, GCD, Google Books, the Open Library index, the publisher catalogs and lookup, verified web or Lens leads, and an agreeing ComicVine issue. Each keeps its own verification, strict where the identity rules require it.
- **What counts as disagreeing.** Another issue number ("001" and "1" agree), another publisher house ("Image", "Image Comics" and "Image Comics, Inc." agree), another year, month or day, other creator names, or different Series wording. Letter-case-only differences and punctuation-only Series differences are kept, per Sergei 2026-10-13. Accents and different words still count as differences. An imprint and its date-applicable parent agree ("Skybound" and "Image Comics"); WildStorm uses Image before 1999 and DC from 1999, and Archaia is independent before 2013. Missing dates do not establish an uncertain parent. A new Imprint is suppressed if it belongs to a different house from the Publisher that will remain, including a human Publisher. An empty source value never replaces.
- **Identity rules.** An identity conflict or a ComicVine hold blocks every field write, replacements included. A dead `Web` link allows writes from strictly verified sources, so it allows replacements from them too.
- **Edits during a pass.** The planned "before" value is the in-book value. Right before the write, the archive must still match the folder scan that planned it and its ComicInfo must still hold that value; otherwise the comic is skipped and planned again (code review F22).
- **Provenance.** The plan entry keeps `replaced` (each field's in-book and new value). The write history and ledger source is `replaced-in-book:<source>`, so a replaced value is never treated as in-book again. Notes gain one sentence naming the source and each old and new value; the earlier in-book Notes stay.
- **v0.1.3 writes.** Written before the ledger existed. At the first folder pass, their verified batch writes are added to the ledger once from `batches/` (the plan entry's source, fields and starting signature; `results.json`'s verified output signature). A write that cannot be matched is never treated as in-book.

The dashboard shows cumulative stage calls, average seconds and total minutes from this update onward. Inventory, source research, local model, synopsis review, and archive writing/verification are measured separately. Parent stages include child stages and concurrent source time overlaps; adding all rows is not elapsed processing time. Evidence reuse and accepted/rejected synopsis reviews have separate counters. These small aggregate records persist across restart.

Newly verified source evidence can be reused for 30 days when the matcher version, comic identity, and sorted archive image names/CRC/size still agree. The record accepts the original identity and the identity produced by filling verified missing fields, so an app XML update does not invalidate it. Changed pages, issue, year, ISBN, title or format reject reuse. Legacy search leads alone are not reusable verified evidence. A reused synopsis source still passes the ordinary quotation and spoiler checks before writing; synopsis text is not inferred from story pages.

For each comic, up to two independent fallback sources run concurrently after ComicVine. Each source retains its existing match verifier and request budgets/pacing/cooldowns. Same-provider API calls remain serialized. Once a verified source succeeds, no additional sources are scheduled; already-running work finishes, with deterministic source priority. Pause stops new scheduling and drains in-flight lookups before acknowledging. Local model work and verified archive writes remain serial. This does not create parallel writers or increase API quotas.

The rolling throughput line counts completed comic research checks separately from distinct comics updated and archive writes. It observes up to the last hour from measurement activation, includes paused/offline time, and uses minute buckets for checks. Multiple writes to one comic count as one updated comic. Check buckets are retained for only seven days; no archive copies or unbounded event logs are created.

## Source scheduling and fair folder retries

Verified identity alone no longer ends fallback research: a result must supply a populated missing field or at least 20 words of source text when the synopsis is missing. This is a scheduling test, not synopsis approval; the same quotation, narrative and spoiler review still gates writes. Thin cached evidence also cannot block richer sources. ISBN lookups prefer the local Open Library index and Google Books; collected editions favor Google Books, and known Dark Horse/Image hints favor their catalogs. All ordinary fallback sources remain available, with at most two concurrent lookups and unchanged request limits.

Per-source retry state is stored with the existing comic research checkpoint. Repeated misses or verified matches without useful new data back off from one day to two, four and at most seven days. Real source errors back off from one hour to at most six hours. Provider-wide blocks remain provider waits, not comic errors: recovery reported as available can wake waiting research early, while an expired but still-unavailable status does not create hourly per-comic retries. A first source attempt still permits its ordinary cached responses. New/changed archive signatures, matcher changes and fresh cover leads reset source backoff. Research already checkpointed before this update gains the new source schedule on its next normally due pass; it is not mass-reset.

Changed files rank alongside new files ahead of unchanged retries in a folder. Continued folder work is placed behind older due folders, rather than monopolizing selection with a zero timestamp. Writes still run before the next research pass, and checkpoints remain durable across pause/restart. A synthetic end-to-end check verifies that a thin cached match is bypassed and useful fields from another verifier enter the serial write queue; it does not demonstrate a new live write.

## Same-pass synopsis completion and exact XML readback

Verified metadata and a separately accepted internet synopsis now share one per-comic plan, digest, archive rewrite and verification. Synopsis review runs in the same pass instead of waiting for a later folder rotation. A rejected synopsis or model error does not discard independently verified metadata. Pause retains an already prepared metadata plan without starting a write. Provider pacing, budgets, identity/cover checks and independent spoiler/quotation review are unchanged.

Jim Henson's Presents #3 failed strict batch readback because its accepted source excerpt contained CRLF paragraph breaks: XML normalizes literal carriage returns to line feeds. The writer now encodes carriage returns as XML character references, preserving the exact text through parsing. It also verifies every supplied field in the temporary archive before replacing the live original or recording a successful write. The live issue was repaired using its previously accepted synopsis; full archive CRCs and unchanged non-XML contents passed. Its retained 65 MB original backup and the repair backup were removed only after verification. The failed queue ticket now records the verified recovery.

Regression checks cover exact CRLF/lone-CR readback, backup cleanup, preservation of the original on temporary metadata verification failure, and one combined plan with an accepted synopsis or metadata alone when review rejects the synopsis. These changes remove a scheduling delay; sustained synopsis completion still depends on sufficient verified internet text and the existing spoiler review.
