# Comics Meta

A local comic metadata tool for YACReader libraries. It scans folders, identifies comics using external sources, writes ComicInfo.xml into CBZ archives, and verifies archive contents before removing temporary backups.

## Setup

Use Python 3.11 or newer on Windows.

```powershell
python -m pip install -r requirements.txt
Copy-Item config.example.json config.json
Copy-Item .env.example .env
```

Fill in the credentials you want to use in `.env`. Set `automatic.root` to your comic folder in `config.json`, then set `automatic.enabled` to true. Start with a small folder of copies to check results before enabling a live library.

```powershell
python app.py
```

The dashboard opens at http://127.0.0.1:8765. Keep the service running. Local configuration, credentials, comics, generated plans and runtime state are excluded from Git.

The header version comes from the running server, captured once from `VERSION` at startup. Editing the checkout cannot relabel an older running process. A backend without version reporting shows **Version unavailable**. This lightweight Python tool uses `VERSION` and `CHANGELOG.md`; Sully owns milestone version changes, commits and pushes. There is no installer/build step. Run offline Python checks with `python -B -m unittest discover -s tests`; actual DOM fixtures require the separately owned headless test harness and make no public requests.

Sources that produced no verified write in the 2026-10-12 review are switched off by default: general free web search, Wikipedia/wiki leads, re-fetching saved leads already rejected for the same archive and identity, GetComics and PREVIEWSworld. New Lens and saved leads are still checked. `config.json` can name its own list, `"sources": {"disabled": [...]}`; an empty list switches every source back on. The code is kept.

When switched on, ordinary free research falls back from DuckDuckGo to Bing using the same comic query. They share the 300/rolling 24-hour cap and minimum 120-second navigation spacing. Yandex is no longer searched (2026-10-12) and the dashboard shows no Yandex verification action; its code, dedicated profile, state table and saved hold are kept. Search links remain leads and never bypass exact comic/source verification. See `SOURCE_CONNECTORS.md` for provider and live-validation limits.

On Windows, double-click `run.cmd` for the persistent launcher. It registers an on-demand task named `ComicsMeta-Local-8765` under your current Windows account and starts the server independently of the launching terminal or client. You can close the launcher window. Windows retries a failed task up to three times, one minute apart. There is no automatic sign-in/startup trigger; start it again after reboot. The saved pause setting remains in effect. Server logs retain one bounded tail from the previous run, and `data/server-exit.json` records observed server exit codes. Pause processing and wait for Paused before stopping the task in Windows Task Scheduler.

## Local model

Install Ollama and download the optional model:

```powershell
ollama pull gemma3:4b
```

Gemma reads cover identification text and selects exact narrative excerpts and checks them for spoilers using internet evidence. Archive story inference (a synopsis composed from pages) is disabled.

In-book identification: when a saved cover reading agrees with the filename, the comic itself is enough. A numbered file gets Series and Number when the cover title and the cover number both agree with the filename; a file without a number is treated as a whole book and gets Series only when the cover title agrees exactly. Creators are never taken from covers, and Year only from an explicit cover date, never a copyright year. Only empty fields are filled. The plan's Notes, the write history source and the research evidence record which field came from where. Set `"in_book": {"cover": false}` in `config.json` to switch this off. Filenames tagged as a translation (for example `[rus]`), a volume, book or part number, a number inside chapter naming, or a reading-order prefix the cover does not show are not written. A cover reading that does not agree remains search evidence only. The ComicVine identity rules come first: a comic whose `Web` names a ComicVine issue, or that is recorded as an identity conflict, is never written by this tier, held or not.

Since Sergei's decisions of 2026-10-13:

- **Cover number not shown as a plain number.** When the cover title agrees with the filename series, Series and Number come from the filename alone (history source `in-book:filename-number`). This applies when the reading has no issue number (empty, a date, a price or a subtitle), or shows the filename's number in other wording ("1 (of 4)", "Issue One", "Origins #08"). Nothing is written when the cover shows another number, another numbering ("Part 2", "Book Two", "Volume 3", "Chapter 6"), an annual or special the filename does not name, text in another script, or a number that may belong to a title ("UNIT 731"). Nothing is written either when the filename's number may not be an issue number: a number in brackets ("(180)"), chapter, episode or part numbering, a catalog title, a collection word (TPB, HC, GN, omnibus), a scan tag, a four-digit number (a year or code), a date code such as `0315`, or a zero-padded decimal. `"in_book": {"filename_number": false}` switches this off.
- **Series spelling.** The Series is the filename's text with obvious slips fixed: possessive `_s` becomes an apostrophe; contractions such as `Don_t Look Back` become `Don't Look Back` when the cover confirms the spelling. Other underscores become spaces, repeated spaces collapse, and stray end separators are removed. Title-final dots and ellipses stay (`Hunt. Kill. Repeat.`, `Midnight, Mass.`, `Beware...`). Accents need the same complete accented title in both cover and indicia readings; a single model reading cannot add them. An alternative title in brackets (`Midlife (or How to Hero at Fifty)`) is kept. The wording is never shortened to the cover title. The evidence and Notes record each fix.
- **Publisher.** Written only when the cover reading and the credits/indicia pages (the pages before the story: credits, legal print block, "Published by", ©) both name the same known publisher in full. A reading that names a second publisher, or only part of a name ("Dark", "Image"), writes nothing. It is on: Sergei switched it on after Futaba's read-only pilot (2026-10-13; when both readings agreed, Metron agreed 164 of 165 times, and the one miss was the imprint Skybound for Image Comics). `"in_book": {"publisher_agreement": false}` switches it off. The credits pages of a comic whose cover names a known publisher are read once with the local model (about 2.7 s per comic), even when the credits tier below is off. A reading that fails (a malformed answer, an unreadable page, over 1,024 generated tokens, over 4,000 characters per field, over 32,000 response bytes or over 30 seconds) counts as no reading, never as agreement, and the same pages are not read again. The printed name is written (Image Comics for a Skybound book). The v0.1.3 `"publisher": true` key, a publisher from one reading, is retired and writes nothing on its own.
- **Outside sources may replace in-book values.** A verified external source (Metron, GCD, a publisher catalog, a verified web page or an agreeing ComicVine issue) replaces a value the in-book tiers wrote when it disagrees. It never replaces values Sergei or another program wrote. A write ledger in the catalog records every verified write: the fields it set, whether Sergei or the service started it, and the archive's size and time before and after. A value counts as in-book only while the archive has changed through the service's own writes since; a manual write or any other program saving the archive makes every value in it stay. Number formats ("001" and "1"), canonical publisher aliases, letter-case-only differences and punctuation-only Series differences are not disagreements. An identity conflict or a ComicVine hold still blocks every field write. The planned value is checked again right before the write, so an edit made during the pass is kept. Notes and the history source (`replaced-in-book:<source>`) record each replacement. Writes made by v0.1.3 are added to the ledger from their batch folders once, at the first folder pass.
- **Imprint.** The main publisher goes in Publisher (Image Comics, DC Comics), the brand line in Imprint (Skybound, Vertigo, Black Label). When a source names a known imprint as the publisher (Metron lists Skybound as one), the write is split: Publisher gets the parent, Imprint the imprint. An imprint and its parent are the same house, so a source saying Skybound does not replace an in-book Image Comics; it fills an empty Imprint instead. The table is small and explicit (`imprints.py`: Skybound, Top Cow, Shadowline and Ghost Machine for Image; Vertigo, Black Label and Young Animal for DC; Icon, Epic, MAX and Marvel Knights for Marvel; BOOM! Box and KaBOOM! for BOOM!; Berger Books for Dark Horse). WildStorm belongs to Image before 1999 and DC from 1999; Archaia is independent before 2013 and belongs to BOOM! from 2013. An unknown publication year leaves these parents uncertain, so neither Publisher nor Imprint is inferred from those brand names. A new Imprint must agree with the Publisher that will remain; a human Publisher from another house is kept without adding a mismatched Imprint. Unknown names are left as they came. Imprint fills empty fields. ComicInfo has had `<Imprint>` since schema 2.0; YACReader 9.13 and later read it and show it in a comic's Properties (Authors tab).

An optional second in-book tier reads the pages after the cover and the last page (credits, indicia, recap) with the local model. It is off by default: `"in_book": {"credits_pages": true}` switches it on, and `"credits_creators": true` also lets it write creators from labelled credits lines. When the indicia names the filename's series and issue number, it writes Series and Number. It writes a publisher only under the agreement rule above. Year and Month (only from a cover date printed right after the issue number, never a copyright year) need `"credits_year": true`, and creators need `"credits_creators": true`; both stay off, because the pilot found 23.5% of recent years and 42.5% of creators right. Covers and editors are never credited. Before switching either on, run the read-only pilot while processing is paused: `python -B pilot_credits.py --out <folder> [--limit 150]`. It compares the tier and publisher agreement with comics an external source verified, measures the model time per comic, and writes only its report.

## Automatic processing

The scheduler progresses folder by folder, checks new or changed files, persists retries and uses a serial write queue. Library traversal is checkpointed in small steps, so discovered folders can be processed before the entire tree has been inventoried. The whole-library walk that finds new folders runs every 6 hours by default (`automatic.inventory_interval_seconds` in `config.json`, at least 600); folders already known keep their own delta scans. The service retries an exited worker every 30 seconds; its lock prevents concurrent writers. Interrupted writes are flagged for inspection instead of blindly replayed.

Eligible comics without an app update in the database write history take priority across folders and within each folder. Coverage passes skip refinements, including in mixed folders. Bounded catalog checks retain the existing research retry windows; refinements resume when no eligible first-update work is found in the inventoried catalog. Waiting readiness snapshots last at most 60 seconds, expire at earlier known retries, and are invalidated by new catalog entries, write history, active tickets, inventory or source availability changes. Existing embedded metadata alone does not count as an app update. Queued work and the current write finish normally.

A folder pass keeps going after its first queued comic: every comic it can update joins one plan and one queue ticket (at most 50), so one write cycle covers several comics. Each entry keeps its own digest, backup, readback and SHA-256 checks. Right before each comic is written, its archive must still match the folder scan that planned it and its ComicInfo must still hold the value each planned field had then (empty, for an automatic plan); a comic changed since then, for example tagged in another program during the pass, is skipped without writing (`skipped.json` beside the plan) and planned again from what it holds now. A comic whose write fails with its archive untouched (duplicate ZIP entries, a leftover temporary file, a page with a bad CRC, a failed temporary-archive check, a replace refused because another program has the comic open) is recorded in `failed.json`. If that attempt had already made its backup, that one backup is removed once the archive and the backup both match the planned SHA-256; no other backup is touched. The comic is offered again after 1, 2, 4 and then 7 days; the fifth failure on the same unchanged archive stops automatic retries until the file changes (repaired, replaced or re-saved); a changed file is due at the next pass. Searching has no final state; this stop applies only to writing an archive that keeps failing. Neither case writes the archive, a skipped comic keeps any backup, and the other comics are still written. An archive that may have been written but did not read back correctly still stops the ticket for inspection, with its backup kept. Within a folder the comics the in-book tier can write come first, then comics Metron can search but has not tried, then missing metadata before already-tagged comics.

ComicVine is consulted only after Metron and only for a comic whose embedded `Web` field carries a ComicVine issue ID; a comic without one is not searched on ComicVine. For a comic with an ID, ComicVine is also the identity check, so it is asked even when Metron answered (from its 30-day cache when possible). Metron's fields wait for that answer. Metron searches also try the series name with " - " and ": " swapped and without a trailing "Vol. N"/"vN" (the Metron series volume must then agree), and a candidate whose main cover differs is checked against its variant covers before it is rejected.

What a comic with a ComicVine ID gets depends on ComicVine's answer. [Source connectors](SOURCE_CONNECTORS.md) § ComicVine identity check has the details.

- **It agrees.** Empty fields are filled.
- **It names another series or number (`identity_conflict`).** No metadata field is written; only an empty Summary can be filled.
- **It cannot answer: an outage, a pause, the hourly budget or a missing key.** The comic is held: nothing is written, Summary included, and it stays `needs_identity_lookup`. The first held pass searches the other sources strictly; later held passes only ask ComicVine again. It is retried after 5, 10, 20 and 40 minutes, then hourly, never before ComicVine's own wait ends; a missing key keeps the daily retry. Once ComicVine answers again, comics held by a ComicVine wait are checked at their folder's next pass.
- **It reports that the issue does not exist (a dead `Web` link).** That is an answer, not an outage: it starts no pause and is remembered for 7 days. Other sources are searched with strict verification and may write, unless a conflict was saved earlier.

The reason for a hold, a dead link, a conflict or a failed write (with its attempt count, next attempt or stop) is saved in the comic's research record (`detail`), with structured fields the dashboard reads (`dead_link`; `hold.next_try_at` and `hold.cause`; `conflict_issue` and `conflict_file`; `write_failures`).

The dashboard's Status filter has two groups (Judy's failure-filter spec, Sergei 2026-10-13). **Needs your help**: Writes stopped, Dead ComicVine link, ComicVine conflict. **Retrying on its own**: Write failed, Held for ComicVine. Count chips under the search row set the same filter. Each comic counts once (stopped, then failed, conflict, dead link, held) and only while its record still describes the file: a changed file is due again and drops out. A comic with a reason shows a badge and one or two sentences under its series name; a held comic's line shows only under the Held filter, and Details shows the reason and the last error. A stopped comic has **Try again**: it clears the stop and keeps the failure count, so one more attempt runs at its folder's next pass and a failure stops it again. It works while processing is paused (the attempt waits for Resume). Status lines under the queue say how many comics need help, how many retry on their own, and when no ComicVine key is set. A key added to `.env` takes effect without a restart.

ComicVine, Metron, GCD, Google Books and publisher/web research are supported. Open Library uses an optional local dump index. See [source connectors](SOURCE_CONNECTORS.md) and [synopsis policy](SYNOPSIS_POLICY.md).

The dashboard shows the configured live scope, working/waiting state, unresolved research and whether a synopsis exists. A completed folder pass or existing metadata does not prove completeness or accuracy. Manual lookups are optional.

**Update statistics** (above Live library, from 0.4.0) shows how many comics the app updated in a period: Last hour, Today (the default), This week, This month, This year, All time or a Custom date range from 1 January 2000. It counts distinct comics in the live library from the write history (one row per verified write since the first one, never pruned), so a comic written several times in a period counts once in the total, and the bars may add up to more than the total. Day, week (Monday start), month and year boundaries are local time; long ranges use the finest of daily, weekly, monthly or yearly bars that fits in 60. The panel reads `GET /api/update-stats` and refreshes every 15 seconds while its period ends now. The counter tile **Currently tagged by this app** (formerly "Updated by this app") is different: it counts comics in that state right now, so it can go down. The comic rows say **Tagged by this app** for the same state (formerly "Updated by this tool").

## Automatic cover search

Reverse-image searches are an identity fallback after database, publisher and web/wiki lookups fail to identify the comic. Missing a synopsis alone does not trigger a reverse search. A comic whose ComicVine issue disagrees with its embedded series and number is searched like an unidentified one. Outstanding requests are cancelled when another source identifies the comic; stale archive requests are discarded before uploading.

Automatic browser cover search is available through `browser_search.enabled`. The independent supervised worker uses Playwright and installed Microsoft Edge (`channel: "msedge"`), with a dedicated profile under `data/lens-profile`. Normal searches run in the background. Only the first archive image is uploaded as a resized cover; archive filenames, folder paths and interior pages are not uploaded.

Searches are paced at least 30 seconds apart (60 by default), capped at 100 attempts per UTC day by default, and successful results are cached for 30 days. Changed archives are rejected. A search that cannot run (cooldown, daily cap or Google human check) is not a result: the comic keeps its queue place and retry wait, records the real reason, and is searched when the hold ends. The daily cap holds searches until the UTC day resets; it starts no cooldown. A search that ran and found nothing usable is retried after one day. Candidate links that all fail identity verification lead to a fresh cover search after the 30-day cache expires; the saved links are re-checked on each daily research pass meanwhile. No cover search ends in a final no-result state. If Google requests human verification, click **Open Google Lens verification** once and complete it yourself in the dedicated window. The request wakes an idle worker; an in-flight search must finish first. The dashboard acknowledges queued/opening requests and disables duplicate clicks. After verification, the window is minimized while its verified session continues automatic searches. Leave it open; no manual action on the uploaded cover is needed. Pause closes it safely. The worker does not solve challenges or spoof fingerprints. Other metadata processing continues. Once you complete the check, the results page Google loads is read, and its links are added as unverified candidates for the comic whose search hit the check. A brief page error while Google redirects after the check no longer fails the attempt; a page error that persists for about a minute ends it with its error class. If you close the window after completing the check, the next search starts a new browser from the same profile.

Upgrading from 0.1.1: 0.1.1 saved searches that never ran as empty results. With processing paused, run `python relabel_cover_tasks.py` (counts only), then `python relabel_cover_tasks.py --apply` to requeue them in the order their searches were blocked. `--rollback` restores the requeued rows that have not changed since.

Lens verification now keeps a durable request receipt separately from ordinary cover progress. The dashboard names the engine and reports queued, opening, open, or failed outcomes; a failed window can be retried after closure is confirmed. Pause generations and service/worker replacement cancel pending intent. The browser worker owns a private Windows Job and exclusive Lens profile lease, and verifies descendant closure before cache maintenance or another launch. Solving Google's check ends the one-hour hold early: Lens searching resumes 5 minutes later (Sergei 2026-10-13). A check that comes back within two hours of the previous solve waits 10, then 20, then 40 minutes, then the full hour; two quiet hours start over. A check left unsolved keeps the hour, and solving never resets the daily cap or request counts.

Dashboard polls cannot overlap within each endpoint. `/api/browser-verification` reports Lens intent independently of aggregate progress. `/api/progress` uses one refresh at a time and lists the 100 most recent write batches, with `completed_total` counting all batches in `data/progress.json`; clients may send `completed_revision` to omit an unchanged `completed` array. `data/progress.json` keeps the 200 most recent batch summaries; older ones move unchanged, in order, to `data/progress-history.jsonl`. Write history itself is in the catalog and each batch's `results.json`. A preparing snapshot returns 503 for a later retry; a failed refresh retains the last full snapshot with `snapshot_stale`. No queue, plan, archive or write-history row is dropped. Neither endpoint returns the Google challenge URL or the comic whose search hit it. Local diagnostic tables `lens_verification` and `lens_verification_events` retain request IDs, timestamps, phases, stages and error classes without raw exception text or challenge URLs.

## Writes and recovery

Use **Pause & release GPU** whenever you need the computer's resources, for games or other work. **Pausing** means the current operation is finishing; a comic write completes verification and backup cleanup before stopping. **Paused** means both workers have stopped processing. The dashboard separately confirms when Gemma has been unloaded from the GPU. Other applications and other Ollama models are unaffected.

The pause setting survives service restarts. Queues, completed writes, research evidence and folder progress are retained. **Resume processing** continues the saved queue and loads Gemma again only when needed. A partially completed batch skips its verified archives after checking that they have not changed. Manual processing actions are blocked while paused. This is a manual control, with no automatic game detection.

ZIP-backed CBZ archives receive metadata writes. Installed 7-Zip enables automatic conversion of CBR/CB7 and RAR/7-Zip containers named CBZ. Conversion checks original archive integrity, decodes comic images, and compares every extracted member's SHA-256 and size against the resulting ZIP before removing the original. A conflicting CBZ is never overwritten. Failed conversions retain originals; same-name replacement rolls back if final readback fails. Each folder pass converts at most one archive.

Existing populated fields are generally preserved; automatic correction of all existing fields is unfinished. The exception is a value the in-book tiers wrote, which a verified external source may replace (§ Local model). Writes preserve page contents and verify the resulting XML and archive integrity. Automatic and manual dashboard updates remove backups after final metadata readback and original-file SHA-256 verification. An automatic write that fails with its archive confirmed unchanged removes its own backup, because the archive still holds the original; interrupted writes, writes that may have replaced the archive, and failed manual writes retain recovery material. Unescaped ampersands in otherwise valid metadata XML are recovered when reading, and forbidden XML control characters are normalized to newlines; later metadata writes serialize valid XML. Cover search uses the supervised Google Lens browser worker.

The list has separate filters for metadata with a synopsis, metadata lacking a synopsis, and a synopsis without other descriptive metadata. These indicate which fields exist, not that every possible field is complete. **Tagged by this app** lists comics in that state now: the app wrote their metadata and the archive has not changed since. It is not write history (that is **Update statistics**), so its count can go down. **Corrupted · Needs reacquiring** is separate from metadata syntax errors and unsupported containers.

## Disk cleanup

The serial worker performs hourly housekeeping. Expired lookup responses are removed, database response payloads and regenerable research caches are each capped at 64 MB, and browser disk/media caches are limited to 64/16 MB. Browser cache directories are cleaned when its context is closed; cookies and session data are preserved. Catalog records, queues, completed write audit records, source evidence, model weights and recovery backups are retained.

Completed conversion attempts remove extraction files immediately. Interrupted conversion staging is eligible for cleanup after 24 hours only when its registered original is still present and unchanged; possible recovery copies remain protected. Stale project temporary files and abandoned test folders are cleaned after 24 hours. Conversion reserves room for extraction and the new CBZ before starting. `data/maintenance.json` records routine cleanup; `conversions` and `conversion_staging` in the catalog record archive conversion and recovery state.

YACReader needs a **Rescan library for XML info** after metadata changes. The app does not directly edit YACReader's database.

`data/` contains the catalog, progress, evidence, quotas and queue. Keep it for continuity; this Git repository backs up code, not local library state. Never publish `.env` or `config.json`.

## Development

```powershell
python -B -m unittest discover -s tests -v
```

Tests cover archive preservation, safe writes, delta scans, matching rejection, quotas, encoding and worker supervision. Tests keep their catalogs and fixtures in temporary folders they remove afterwards; no test writes this checkout's `data/`. Browser layout changes and human-verification challenges can interrupt free cover searches. Uncertain identities remain unresolved; source availability and coverage vary.
